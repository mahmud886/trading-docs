## What Is Walk-Forward Analysis?

When you optimise a strategy, you fit it to past data, and the fitted result flatters it (see [Backtesting Methodology](/en/quantitative/backtesting-methodology)). **Walk-forward analysis** tests the **procedure** instead:

1. **Optimise** on an in-sample window (for example the last 250 bars) and pick the best parameters.
2. **Trade** those parameters on the next, unseen out-of-sample window (for example 60 bars).
3. **Step forward** by the out-of-sample length and repeat.
4. **Chain** all the out-of-sample segments into one equity curve.

That chained curve contains only results the optimiser had no way of fitting to, so it is a fairer estimate of what re-optimising in real time would have produced.

<Callout type="warning" title="Corrected and toned down">
  The original called walk-forward the "gold standard" for validation and gave fixed efficiency thresholds. It is a
  considerably better test than a single in-sample optimisation, but it is not a guarantee: the whole walk-forward
  record is still one historical path, and if you tune the window lengths until the result looks good, you have overfit
  the procedure itself.
</Callout>

## An Example With 35 Rules and 19 Windows

The prices are synthetic: 1,400 daily bars with a weak, drifting trend and noise. The rules are 35 moving-average crossovers (fast 5–25, slow 30–120, long when the fast average is above the slow one, else short, no costs). Each window optimises on 250 bars and trades the next 60.

Reading the table: the whole-sample "best" rule looks better (+48%), but you could only have picked it by looking at the whole period, including the future. The walk-forward record is the one you could actually have traded. It still **beat buy-and-hold** here, but it reached about +50% by day 1,050 and then **gave most of it back**, a 32% drawdown: a reminder that a positive walk-forward result is not smooth.

## Parameter Stability

The bottom panel is as important as the equity curve. The optimiser picked a slow length of 45, 75, 30, 120, 105, 60, 90 and so on: **10 changes in 18 steps**, ranging from 30 to 120. When the "best" parameter jumps around like that, the optimiser is chasing noise in each window, which is a warning that the rule's edge, if any, is weak and not tied to a specific setting.

| What you see                                      | What it suggests                                    |
| ------------------------------------------------- | --------------------------------------------------- |
| Chosen parameters stay in a narrow band           | The edge is not very sensitive to the exact setting |
| Chosen parameters jump across the grid            | The optimiser is fitting noise                      |
| Out-of-sample far below in-sample in every window | Overfitting                                         |
| Walk-forward positive but with deep drawdowns     | Expect a bumpy ride; size accordingly               |

## Design Choices

| Choice               | Consideration                                                                 |
| -------------------- | ----------------------------------------------------------------------------- |
| In-sample length     | Too short = noisy picks; too long = slow to adapt                             |
| Out-of-sample length | Short gives more windows; long reduces transaction frequency                  |
| Anchored vs rolling  | Anchored keeps all past data; rolling forgets the old                         |
| Optimisation target  | Total return picks lucky rules; risk-adjusted or robust measures are steadier |
| Costs                | Include them in every window                                                  |

### Example (no chart) — acting on a walk-forward result

The latest window chose fast 25 / slow 120 and the fast average is above the slow one, so the rule is long. Plan: buy EUR/USD at **1.0850**, stop **1.0800** (50 pips), target **1.0950** (100 pips): **1 : 2.0** planned. Because the chosen slow length has moved from 30 to 120 across windows, treat this signal as a low-confidence one: trade at reduced size and expect the rule to be re-optimised and possibly replaced after the next 60 bars.

## Common Mistakes

| Mistake                                                     | Fix                                                      |
| ----------------------------------------------------------- | -------------------------------------------------------- |
| Choosing window lengths to maximise the walk-forward result | Fix them in advance, or test several and report them all |
| Reporting only the whole-sample optimum                     | Report the walk-forward curve                            |
| Ignoring parameter stability                                | Chart the chosen parameters across windows               |
| Treating walk-forward as proof                              | It is one path; follow with small live trading           |
| Forgetting costs                                            | Include them in each window                              |

## Practice

1. Take one rule family you use (for example moving-average crossovers). Run a walk-forward with 250 in-sample and 60 out-of-sample bars.
2. Compare the chained out-of-sample result with the best rule on all the data.
3. Chart the chosen parameters. How stable are they?
4. Log it in your [trading journal](/en/tools/journal-template).

## Summary

| Idea           | Detail                                                                |
| -------------- | --------------------------------------------------------------------- |
| Walk-forward   | Optimise on a window, trade the next, step forward, chain the results |
| Why            | The chained curve only contains unseen data                           |
| Example result | +16% vs +48% for the best whole-sample rule (which needed the future) |
| Check          | Parameter stability and drawdown, not just the end number             |
