## What Is Equity Curve Management?

**Equity curve management** adjusts how much you trade — or whether you trade — based on how your own equity curve is behaving. The common forms are:

| Technique               | Rule (example)                                                        | Aim                                      |
| ----------------------- | --------------------------------------------------------------------- | ---------------------------------------- |
| **Equity-curve filter** | Trade only while the equity curve is above its N-trade moving average | Stop trading through a bad stretch       |
| **Drawdown scaling**    | Cut risk per trade by half once drawdown passes a threshold           | Slow the damage                          |
| **Pause rule**          | Stop trading after a drawdown of X until a review is done             | Force a check that the edge still exists |
| **Scaling up**          | Raise risk modestly when the curve makes new highs                    | Press an edge that seems to be working   |

<Callout type="warning" title="Corrected and toned down">
  The original gave fixed rules ("reduce size beyond 1 SD", "pause beyond 2 SD") as if they were standard. Those are
  choices, not laws, and the evidence for them is mixed. An equity-curve rule can reduce drawdown, but it does not
  create an edge, and it can skip the recovery. This lesson measures both effects.
</Callout>

## A Worked Example: A Fading Edge

The system takes 300 trades with wins of +1.5R and losses of −1R. The win rate is **50%** in trades 1–100, **33%** in trades 101–200 (negative expectancy: 0.33 × 1.5 − 0.67 = −0.17R), and **50%** again in 201–300. The filter rule is: take the next trade only if the equity curve of **all signals** is above its **20-trade moving average**; skipped trades still update that "virtual" curve.

| Measure                              | Always trade | With the filter                                     |
| ------------------------------------ | ------------ | --------------------------------------------------- |
| Trades taken                         | 300          | 156                                                 |
| Final result                         | +12.5R       | +19R                                                |
| Maximum drawdown                     | 23.5R        | 15.5R                                               |
| Result in the weak stretch (101–200) | about −18R   | the filter skips most of it: trades taken 22 of 100 |

In this sequence the filter skipped 78 of the 100 trades in the weak stretch and ended ahead. That is the flattering case. The same system and rule on **1,000** random sequences gives:

| Over 1,000 simulated sequences          | Result |
| --------------------------------------- | ------ |
| The filter lowered the maximum drawdown | 92%    |
| The filter gave a higher final result   | 50%    |
| Average reduction in maximum drawdown   | 13.7R  |
| Average difference in final result      | +1.3R  |

So the dependable effect is **a smaller drawdown**. The effect on profit is close to a coin flip: when the edge truly fades, the filter helps; when a drawdown is just noise, it **skips the recovery** and costs money.

## Choosing and Testing the Rule

| Parameter / choice      | Consideration                                                                                 |
| ----------------------- | --------------------------------------------------------------------------------------------- |
| Averaging window        | Short = twitchy and skips too much; long = slow to react                                      |
| Using the virtual curve | You must keep tracking skipped trades so the filter can turn back on                          |
| Re-entry rule           | Define exactly when you resume                                                                |
| Test out-of-sample      | The rule has its own parameters — see [Backtesting](/en/quantitative/backtesting-methodology) |

### Example (no chart) — a risk-scaling rule

Rule: normal risk is **1%** per trade; when the equity curve is more than **10R** below its peak, risk **0.5%**; return to 1% when it makes a new peak. Entry **1.0850**, stop **1.0830** (20 pips), target **1.0880** (**1 : 1.5** planned): in drawdown, the same trade is sized at half the risk (on a 10,000 account, 50 instead of 100, i.e. 2.5 per pip instead of 5). If the edge returns the cost is slower recovery; if it has gone, the saving is about half the further loss.

## Common Mistakes

| Mistake                                 | Fix                                                   |
| --------------------------------------- | ----------------------------------------------------- |
| Stopping tracking when you stop trading | Track every signal so the rule can resume             |
| Assuming a filter adds profit           | Mostly it trims drawdown; test the profit effect      |
| Tuning the window on the same data      | Test out-of-sample and across many sequences          |
| Changing rules mid-drawdown             | Decide the rule beforehand                            |
| Treating a pause as a verdict           | A pause is a review point, not proof the edge is gone |

## Practice

1. Chart your last 100 trades as an equity curve in R with its 20-trade average. How often is the curve below its average?
2. Apply the filter rule to your history: how many trades would it have skipped, and what R did they carry?
3. Simulate your own trade list in random order 1,000 times and compare drawdown and final result with and without the rule.
4. Log it in your [trading journal](/en/tools/journal-template).

## Summary

| Idea          | Detail                                                                       |
| ------------- | ---------------------------------------------------------------------------- |
| Management    | Trade less or smaller when your own equity curve is weak                     |
| Evidence here | Max drawdown lower in 92% of simulated sequences; final result better in 50% |
| Cost          | It can skip recoveries; keep tracking skipped trades                         |
| Use           | A drawdown-control tool, not an edge                                         |
