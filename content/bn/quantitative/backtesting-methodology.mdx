## কেন Backtest বিভ্রান্ত করে

**Backtest** অতীত ডেটায় নির্দিষ্ট নিয়ম প্রয়োগ করে। এটি দেখাতে পারে একটি নিয়ম **কী করত**; নিয়মটির Edge আছে তা দেখাতে পারে না। বিপদ এই নয় যে Backtest এর অঙ্ক ভুল, বরং এটি ভালো দেখানো পর্যন্ত **টিউন করা** খুব সহজ।

<Callout type="warning" title="সুর নরম করা হয়েছে">
  মূল লেসনে Backtesting কে Bias "এড়ানোর" উপায় বলা হয়েছিল। কোনো পদ্ধতি একে পুরোপুরি সরায় না; লক্ষ্য হলো কমানো আর কতটা
  বাকি তা জানা। "১০০ ট্রেড যথেষ্ট" এর মতো স্থির নিয়ম মান নয়।
</Callout>

## প্রচলিত Bias

| Bias                            | কী                                                                                         | কীভাবে কমাবেন                                                 |
| ------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| **Look-ahead**                  | সিদ্ধান্তের সময় জানা ছিল না এমন তথ্য ব্যবহার (যেমন আজকের এন্ট্রির সিদ্ধান্তে আজকের Close) | বার _t_ এ সিদ্ধান্ত, বার _t + ১_ এ ট্রেড; টাইমস্ট্যাম্প যাচাই |
| **Survivorship**                | শুধু এখনো টিকে থাকা ইন্সট্রুমেন্ট পরীক্ষা, ব্যর্থগুলো বাদ                                  | ডিলিস্টেড সহ Point-in-time ইউনিভার্স ব্যবহার                  |
| **Overfitting / Data Snooping** | যে ডেটায় বিচার করা হয় তাতেই নিয়ম বা প্যারামিটার টিউন                                    | Out-of-sample টেস্ট, কম প্যারামিটার, চেষ্টা গোনা              |
| **Multiple Testing**            | অনেক নিয়ম চেষ্টা করে শুধু সেরাটি জানানো                                                   | চেষ্টার সংখ্যার জন্য সমন্বয়                                  |
| **খরচ উপেক্ষা**                 | স্প্রেড, কমিশন, স্লিপেজ, ফাইন্যান্সিং                                                      | প্রতি ট্রেডে বাস্তবসম্মত খরচ ধরুন                             |
| **অবাস্তব ফিল**                 | যে লেভেল চেয়েছিলেন সেখানেই ফিল ধরা                                                        | Bid/Ask ব্যবহার, স্লিপেজ যোগ, তারল্য যাচাই                    |
| **রেজিম নির্ভরতা**              | যে নিয়ম শুধু এক মার্কেট অবস্থায় কাজ করেছে                                                | কয়েকটি রেজিমে পরীক্ষা                                        |

## একটি প্রদর্শন: নয়েজে ১৮০টি নিয়মের সেরা

<Callout type="info" title="এই চার্ট সম্পর্কে">
  প্রাইস **সিন্থেটিক Random Walk**: গঠনগতভাবে কোনো স্ট্র্যাটেজির Edge নেই। ১৮০টি Moving-average ক্রসওভার নিয়ম (fast
  ৩–২০ × slow ২৫–৮১) খরচ ছাড়া প্রথম ৫০০ বারে পরীক্ষা করা হয়েছে, আর সেরাটি পরের ৫০০ বারে অনুসরণ করা হয়েছে। ফল
  র‍্যান্ডম সিডের ওপর নির্ভর করে; সংখ্যা নয়, প্যাটার্নই মূল কথা।
</Callout>

| পরিমাপ                                 | মান                                  |
| -------------------------------------- | ------------------------------------ |
| পরীক্ষিত নিয়ম                         | ১৮০                                  |
| In-sample সেরা নিয়ম                   | Fast 3 / slow 25                     |
| এর In-sample ফল                        | প্রায় ৪৭৫ ট্রেডিং দিনে +৫০%         |
| এর Out-of-sample ফল                    | পরের ৫০০ দিনে +৬%                    |
| ১৮০টি নিয়মের গড়                      | In-sample এ +৫%, Out-of-sample এ −৩% |
| t-statistic, In-sample / Out-of-sample | ১.৯ / ০.৪                            |

**t-statistic** হলো গড় দৈনিক রিটার্ন ভাগ তার Standard Error (Standard Deviation ÷ √n)। মোটামুটি নিয়ম: |t| প্রায় ২ এর বেশি হলে "একক পরীক্ষায় কাকতালীয় হওয়ার সম্ভাবনা কম"। কিন্তু ১৮০টি স্বাধীন নয়েজ ফলের সেরার প্রত্যাশিত |t| প্রায় **√(২ ln ১৮০) ≈ ৩.২**: তাই ১৮০টির সেরার জন্য ১.৯ এর t-ও কাকতালীয়ভাবে সাধারণত যা আসে তার **চেয়ে কম**। Out-of-sample এর ০.৪ হলো Edge-হীন নিয়মের চেহারা।

## একটি সঠিক পদ্ধতি

| ধাপ | কী করবেন                                                                                                   |
| --- | ---------------------------------------------------------------------------------------------------------- |
| ১   | ফল দেখার আগে নিয়ম ও প্যারামিটারের সংখ্যা লিখুন                                                            |
| ২   | ডেটা ভাগ করুন: একটি অংশে বানান, বাকিটা অস্পৃষ্ট রাখুন                                                      |
| ৩   | চেষ্টা করা প্রতিটি নিয়ম ও প্যারামিটার সেট গুনুন (এটি আপনার Multiple-testing বোঝা)                         |
| ৪   | খরচ ও বাস্তবসম্মত ফিল ধরুন                                                                                 |
| ৫   | বেছে নেওয়া নিয়ম সংরক্ষিত ডেটায় একবার পরীক্ষা করুন ([Walk-Forward](/bn/quantitative/walk-forward) দেখুন) |
| ৬   | তারপর ছোট সাইজে ট্রেড করে লাইভ ফল Backtest এর সাথে মেলান                                                   |

### উদাহরণ (চার্ট ছাড়া) — Backtest সৎভাবে পড়া

২০০ ট্রেডের Backtest এ খরচের আগে Expectancy +০.৩০R। খরচ প্রতি ট্রেডে ০.১০R, তাই খরচের পর **+০.২০R**। সেখানে পৌঁছাতে ৪০টি প্যারামিটার সেট চেষ্টা করেছেন, তাই +০.৩০R হলো ৪০টির _সেরা_, গড় নয়, আর এটি ছাড় দিতে হবে। পরীক্ষার পরিকল্পনা: এন্ট্রি **1.0850**, Stop **1.0830**, টার্গেট **1.0880** (১ : ১.৫), আরও ১০০ ট্রেড ছোট সাইজে করে তুলনা করুন। লাইভ Expectancy Backtest এর অনিশ্চয়তার মধ্যে থাকলে চালিয়ে যান; শূন্যের কাছে হলে থামুন।

## অনুশীলন

1. আপনার পছন্দের একটি সরল নিয়ম নিন। সেরা ফল পেতে যে প্রতিটি প্যারামিটার বদলেছেন তা তালিকা করুন।
2. ডেটার শেষ ৩০% সরিয়ে রাখুন। বেছে নেওয়া নিয়ম তাতে একবার চালান।
3. প্রতিটি অংশে দৈনিক রিটার্নের t-statistic হিসাব করুন।
4. আপনার [ট্রেডিং জার্নালে](/bn/tools/journal-template) লিখুন।
