## কেন Monte Carlo?

একটি Backtest হলো **একটি পথ**: ট্রেডগুলো যে নির্দিষ্ট ক্রমে ঘটেছে। একই ট্রেড ভিন্ন ক্রমে, বা একই Edge থেকে ভিন্ন নমুনা, ভিন্ন Equity কার্ভ ও ভিন্ন Drawdown দিত। **Monte Carlo** সিমুলেশন এমন অনেক পথ তৈরি করে যাতে আপনি শুধু যেটি ঘটেছে সেটি নয়, ফলের **পরিসর** দেখতে পান।

<Callout type="warning" title="সংশোধিত ও নরম করা হয়েছে">
  মূল লেসনে বলা হয়েছিল Monte Carlo আসল ট্রেডিংয়ের "ধ্বংসের ঝুঁকি" ও "কনফিডেন্স ইন্টারভাল" দেখায়। Resampling শুধু
  **আপনার হাতে থাকা ট্রেডগুলোকেই** আবার সাজায় বা আবার তোলে। আপনার তালিকার সবচেয়ে খারাপ ট্রেডের চেয়ে বড় লোকসান এটি
  তৈরি করতে পারে না, আর ধরে নেয় ভবিষ্যৎ নমুনার মতো হবে। আউটপুটকে পথের ঝুঁকির মোটামুটি গাইড ধরুন, প্রকৃত ধ্বংস-সম্ভাবনার
  পরিমাপ নয়।
</Callout>

## Bootstrap পদ্ধতি

| ধাপ | কী করবেন                                                                                        |
| --- | ----------------------------------------------------------------------------------------------- |
| ১   | প্রতিটি ট্রেডের R-গুণিতক সংগ্রহ করুন (ফল ÷ ঝুঁকির পরিমাণ)                                       |
| ২   | একই দৈর্ঘ্যের নতুন ক্রম বানাতে ট্রেড **Replacement সহ** তুলুন                                   |
| ৩   | সেই পথের চূড়ান্ত ফল ও **সর্বোচ্চ Drawdown** (সবচেয়ে বড় শীর্ষ-থেকে-তলদেশ পতন, R এ) হিসাব করুন |
| ৪   | হাজার হাজার বার পুনরাবৃত্তি করুন                                                                |
| ৫   | Percentile পড়ুন: ৫ম, ৫০ম (মিডিয়ান) ও ৯৫ম                                                      |

বিভিন্নতা: **Replacement ছাড়া Shuffle** (একই ট্রেডের সেট রাখে, শুধু ক্রম পরীক্ষা করে), বা **Block Bootstrap** (লোকসানের গুচ্ছ বজায় রাখতে ট্রেডের ধারা Resample)।

| -------------------------- | ------------- | -------- | -------------- |
| ১০০ ট্রেডের পর চূড়ান্ত ফল | −৮R           | +১২R     | +৩২R           |
| সর্বোচ্চ Drawdown          | ৫R            | ৯R       | ১৮R            |

অন্য ফল: Expectancy ধনাত্মক হলেও Resampled পথের **১২%** **শূন্যের নিচে** শেষ হয়, আর **১২%** এর Drawdown **১৫R এর বেশি**। ৯৫ম-Percentile Drawdown (১৮R) Backtest এ দেখা ৭.৫R এর **দ্বিগুণের বেশি**: Backtest ছিল মোটামুটি সদয় একটি পথ।

## R থেকে অ্যাকাউন্ট Drawdown

প্রতি ট্রেডের **ঝুঁকি** ঠিক করলে R এ Drawdown অ্যাকাউন্টের শতাংশে পরিণত হয়: মোটামুটি ১ − (১ − r)^D, যেখানে _r_ ঝুঁকির ভগ্নাংশ আর _D_ R এ Drawdown (এটি চক্রবৃদ্ধি হয়)।

| প্রতি ট্রেডে ঝুঁকি | ৯R (মিডিয়ান) | ১৮R (৯৫ম Percentile) |
| ------------------ | ------------- | -------------------- |
| ০.৫%               | ৪.৪%          | ৮.৬%                 |
| ১%                 | ৮.৬%          | ১৬.৫%                |
| ২%                 | ১৬.৬%         | ৩০.৫%                |
| ৩%                 | ২৪.০%         | ৪২.২%                |

### উদাহরণ (চার্ট ছাড়া) — প্রতি ট্রেডের ঝুঁকি বাছা

৯৫ম Percentile এ **২০%** Drawdown সহ্য করতে পারেন। ১ − (১ − r)^১৮ = ০.২০ সমাধান করুন: r = ১ − ০.৮^(১/১৮) ≈ **১.২৩%**, তাই প্রতি ট্রেডে প্রায় **১.২%** ঝুঁকি। একটি ট্রেড: এন্ট্রি **1.0850**, Stop **1.0830**, টার্গেট **1.0880** (পরিকল্পিত **১ : ১.৫**); ১০,০০০ অ্যাকাউন্টে এতে ১২০ ঝুঁকি, আর পজিশনের সাইজ ১২০ ÷ ২০ পিপ = প্রতি পিপে ৬। লাইভ Drawdown সিমুলেটেড ৯৫ম Percentile ছাড়ালে ধরুন Edge বা অনুমান বদলে থাকতে পারে।

| সীমা                   | বিস্তারিত                                                                  |
| ---------------------- | -------------------------------------------------------------------------- |
| শুধু আপনার হাতের ট্রেড | নমুনার সবচেয়ে খারাপের চেয়ে বড় লোকসান নেই                                |
| স্বাধীনতা              | সাধারণ Resampling লোকসানের গুচ্ছ উপেক্ষা করে; Block Bootstrap ব্যবহার করুন |
| ছোট নমুনা              | ১০০ ট্রেড চওড়া, এলোমেলো Percentile দেয়; বেশি ট্রেড সংকীর্ণ করে           |
| Edge বদলাতে পারে       | Resampling ধরে নেয় ভবিষ্যৎ নমুনার মতো                                     |
| খরচ ও স্লিপেজ          | খরচের পরের ট্রেড ব্যবহার করুন                                              |

## সাধারণ ভুল

| ভুল                                         | সমাধান                                           |
| ------------------------------------------- | ------------------------------------------------ |
| শুধু Backtest এর Drawdown জানানো            | Monte Carlo এর Percentile পরিসর জানান            |
| Drawdown চক্রবৃদ্ধি হয় তা উপেক্ষা          | প্রতি ট্রেডের ঝুঁকি দিয়ে R কে % এ রূপান্তর করুন |
| খরচের আগের ট্রেড ব্যবহার                    | খরচের পরের R ব্যবহার করুন                        |
| ৯৫ম Percentile কে সবচেয়ে খারাপ ক্ষেত্র ধরা | লেজ আরও খারাপ হতে পারে; মার্জিন রাখুন            |
| একই ডেটায় অপ্টিমাইজ করা নিয়ম Resample     | Out-of-sample ট্রেড Resample করুন                |

## অনুশীলন

1. আপনার ট্রেড R-গুণিতক হিসেবে এক্সপোর্ট করুন। ১০০ ট্রেডের ৫,০০০ পথ Resample করে চূড়ান্ত R ও সর্বোচ্চ Drawdown এর ৫ম, ৫০ম ও ৯৫ম Percentile লিখুন।
2. ৯৫ম-Percentile Drawdown কে আপনার স্বাভাবিক ঝুঁকিতে শতাংশে রূপান্তর করুন।
3. আপনার আসলে দেখা সবচেয়ে খারাপ Drawdown এর সাথে তুলনা করুন। এটি কি পরিসরের ভেতরে?
4. আপনার [ট্রেডিং জার্নালে](/bn/tools/journal-template) লিখুন।
